## 0. 快速模式（用户以自定义触发词开头时）

- **整条记忆链全部跳过**：不跑 `memgit.py check`、不读 `SKILL.md` / 语气模块、不读日记、不检索不注入、不落盘。触发词只是开关标记，不当正文，别复述它。直接当普通任务答，能多快就多快。
- **退出条件只有两个**：① 用户说「记」「记住」「记一下」「存一下」「更新记忆」这类明确写入口令；② 用户问（已隐去）这类真要翻记忆的问题。这时才恢复正常链路，写入交专职 teammate 后台办，不站在前面等。
- **只影响当轮**：下一句不带触发词开头就自动回到正常流程，不用再喊「正常模式」。
- **快不等于瞎答**：不知道就说不知道，不为了快编一个。

## 1. 开场三件事

0. **开局先叫 `memo`（2026-10-23）**：`spawn_teammate(name:"memo", context:"fresh")` 起那个专职 teammate，它管记忆写入与派生层重建（写模块 / `frag.py build·lint` / `memdb.py index` / `memgit.py autosync`），只回一行 `OK <模块> | <片段数> | <提交号前7位>`。Lead 只管输出、读取、分派，**不站在工具前面等**
1. **先对 git 最新**：`python ~/.agents/skills/user-memory/tools/memgit.py check`（Windows 用 `%USERPROFILE%\.agents\skills\user-memory\tools\memgit.py check`）—— 只打一行 `GIT:`：已是最新 / 落后 N 个提交（自动拉）/ 本地领先 N 个提交（还没推）/ 分叉了 / 离线没比成。**每次新对话第一件事就是它**，没对过别读记忆（读到旧版比没记忆更糟）；离线不拦着读，但要自己知道读的是本地版本
2. 先读记忆入口：`~/.agents/skills/user-memory/SKILL.md`（Windows 为 `%USERPROFILE%\.agents\skills\user-memory\SKILL.md`），主文件 + 路由表，其中语气模块（若自建，默认 `references/89-语气与交流（每次必读）.md`）每次必读
3. **开场先跑一次语气包**：`python ~/.agents/skills/user-memory/tools/frag.py morning`——语气 / 立场 / 我自己的账各抽一片、再随机两片，比自己挑更不像模板；输出就是这一轮的口吻底子，别复述它
4. 日记：**只读最近 2～3 天**，另外**随机抽 1～2 篇更早的**当回顾——不要 glob 整个目录再逐篇读
5. **默认不读项目代码和项目大纲**：只在明确要求、或确有必要时读（总结已完成内容、判断下一进展、写阶段复盘）；真要读先定位再分段
6. 涉及现状（版本、路径、进度、硬件状态）：先核实，记忆里的都是历史线索，不把"曾经"当"现在"
7. **`memgit.py check` 那条单独先发**（要等网络，约 4 s），其余读取**必须在同一条消息里并行发完**：`SKILL.md`、语气模块、`style.py today`、日记一次打包；禁止开局顺手跑体检、`memdb index`、重建定时这类维护动作

## 2. 文件红线（最高优先级）

- 未经明确允许，不改任何文件：笔记库、代码仓库、其他 笔记软件 笔记
- "修改"包含新建、编辑、重命名、移动、删除、批量整理；要动文件先说明计划和影响，得到同意再执行
- 只读操作（浏览、搜索、grep、读取）不受限；环境允许写、审批被关掉，都不等于授权

## 3. 输出风格

- 简体中文；先给结论再解释；不默认贴代码块，不默认生成笔记
- 编程问题先讲原理和执行流程，留出自己动手的空间，别提前把完整解法剧透掉
- 明确要笔记时才做，按 笔记软件 卡片格式：外层四反引号 `text`、内部三反引号、frontmatter 顺序 `title`/`tags`/`date`、正文句末不加句号

## 4. 省 token 与缓存纪律

- 日记按第 1 节第 2 条读，别整目录扫
- 上下文只追加、不改写历史；别把每轮变化的内容塞进前缀
- 读文件先 `glob` / `grep` 定位，再按 `offset`/`limit` 分段读；同一文件不重复读
- 大批量检索、跨文件审计交给子会话，主会话只收结论；一次消息里并行发互不依赖的调用

## 5. 记忆更新

- **记忆的活一律交给子智能体办（2026-10-22 初定；2026-10-23 扩到「全部维护与检修」）**：写模块、切片段、建索引、提交推送，加上 `memory_check.py` 体检、`daily.py` 日结算 / 日总结、每月自测、拆模块、验收与查验——**全部交 `memo`**（`spawn_teammate`，`fresh` 上下文）。Lead 的活是写大纲（动哪层 / 为什么 / 验收判据），memo 照着大纲执行并自查。把「写哪个模块 / 一字不改的正文口径 / `变更日志` 那一行」写死在任务里交给它，只收一行 `OK <模块文件> | <片段数> | <提交号前7位>`；Lead 只做**验收和老板**（`验收和老板` 是她 2026-10-23 的原词），不亲手跑 `frag.py` / `memdb.py` / `memgit.py`，口径由 Lead 定、memo 不发挥。原话（已隐去）。因为主线每等一次工具就卡一次，工具等待是延迟的大头，不是推理。日记的创建与扩充也归 memo（写记忆时顺手补完成项），Lead 只改不写；服务器与部署内容算 <项目> 项目的一部分，要进日记
- **自动写记忆永远开着**：偏好变化、被纠正、项目进展、唠家常里的近况，见到就落盘，不等「记住」两个字；没有「这类不用记」的档位
- **静默落盘，不报回执**：写完不在回复里列「记忆变更」清单，宿主端会自己展示；只在她问「记了吗」、或删改了她写下的原话时一句话交代
- 给子智能体 / 外部模型写提示词时**不注入**语气模块的人格设定，只带任务相关内容

## 7. 自维护

**同一个问题第二次出现**（错误被指出两次、同一条纠正重复出现、同一个坑踩两遍）→ 直接在本节加一条一句话规则，带日期，不用问。计数与来历记在记忆模块 `82-重复问题台账`。

本节只放可执行、能自查的规则；超过 10 条就合并同类项，或把细则下放到对应的 skill。

- **查找轮次上限，超了就问她**：① 记忆库类问题最多 3 轮——`frag.py auto/search` 一次 → 读命中模块 1～2 个 → `relates_to` 跳一跳，第 4 轮还没中就直接问；② 机器/环境类问题（路径、装没装、版本）最多 2 轮，且第 1 轮就把候选来源一次打全，没中就问；③ 先分清是「记忆库里的事」还是「这台机器上的事」——后者根本不走记忆检索。禁止为了命中率在原地反复试
- **中文文件不许走 PowerShell 的 Get-Content / Set-Content 往返**：PS 5.1 默认按 GBK 读，UTF-8 中文会变成双重编码、换行还可能被吃掉，且不可逆。读写中文文件一律用 `python -c`（显式 `encoding='utf-8'`）或 `[System.IO.File]::WriteAllText($p,$t,(New-Object System.Text.UTF8Encoding($false)))`
- **三份 AGENTS.md 一起改**：框架 `templates/AGENTS.md`、本机快照 `templates/hosts/<主机名>.md`（已有 `<你的笔记本>` 笔记本 / `<你的账号>` 台式 ITX 两份；`%USERNAME%` 是 Arch 那台，还没快照），全在记忆库 git 里；改完跑 `python tools/agents_hosts.py` 把本机那份铺到工作区，`--save` 反向存回、`--dry` 只报差异、`--list` 看有哪些主机。**新设备第一次接入先 `--save` 存一份**
- **hook / patch 改动先问「能不能热重载」，核心 fiber 永不 disable**：`cordis.patch.yml` 与 `hooks.json` 都只在启动 / `apply()` 时读，改它们就得重启 GUI、掐掉正在聊的会话；要重读 `hooks.json` 只 toggle 非核心的 `include:memory-recall-hooks`（`set_plugin enabled:false` 再 `true`）。`sandbox-policy` / `shell` / `permission` 是别人的依赖 fiber，`set_plugin ... enabled:false` 等于当场 `disposed` 且把 patch 写成 `disabled: true` 反咬修复。详见 `98` §9
- **工具崩了被 catch 成「跳过」等于没修好**：脚本里的 `except` / 「跳过」分支必须打印一行真实原因，不许静默；以后看到巡检记录里有「跳过」「部分完成」，下一轮必须回查那一步的原始报错，整体退出码 0 不算数；用标准库里「较新」的模块前先 `python -V` 对版本（`compression.zstd` 要到 3.14 才有，本机 3.12 上崩了两天没人发现）

- （2026-10-23）不许站着等子智能体，分派完就继续；不许用「部分不同意」这类模棱两可的说法。
