# 打包与分发

> 把这份记忆库发给别人（或搬到公开仓库）时读：哪些算个人信息、哪些清空、命令怎么跑。
>
> **以后要开源的话**：根目录 `README.md` 就是给外人看的入口（用途、装法、目录结构、打包表），本模块只管「哪些不能带出去」。发公开仓库前跑一次 `pack.py --no-zip` 抽检，别直接把本机目录 push。

## 一句话

每个模块 frontmatter 里的 `distribute:` 决定打包命运，`tools/pack.py`（跨平台）或 `tools/pack.ps1` 按它执行，人不用记清单。

**默认判据（2026-10-20 定的）：个人记忆一律不发。** 协议件之外，`0x`–`8x` 的主题模块默认 `drop`——身份、背景、学习线、升学规划、命名偏好、历史搬运件，全是「这个人自己的资料」，不是「记忆框架」；想要哪份自己改 `distribute:` 就多留哪份。

发出去的是**能装记忆、能自己维护的空壳**：协议、检索、备份、打包、片段层、两个空槽位和三张空表。

| 值 | 打包后长什么样 | 用在哪些模块 |
| --- | --- | --- |
| `keep` | 原文保留（路径换占位符） | 纯机制：`SKILL`、`90` 检索、`91` 迁移、`91a` 骨架、`92` 打包、`92a` 人格包、`93` 自动注入、`95` 参考资料、`96` 安全墙、`97` 检索评测、`98` hook 验收、`99` 架构大纲、`_模板`（2026-10-21 补后五项：之前只列到 `92`，实际 `93`/`95`/`96`/`97`/`98`/`99` 都是 keep） |
| `blank` | 只留 frontmatter + 标题 + 引言，正文清空 | 三个最基础槽位：`01` 身份、`11` 日常、`31` 性格侧写 |
| `reset` | 保留结构（表头 / 小节），记录清空 | `变更日志`、重复问题台账 `82`、待确认 `_待确认` |
| `drop` | 整个文件不发 | **默认值**——语气/人格 `89`/`88`/`87`、学习偏好 `02`、技术学习线 `03`–`09`、私有项目 `07`、健康 `10`、AI 用量 `13`、碎碎念 `84`、自维护节律 `83`、主动话题 `79`、斗图 `80`、风格轮换 `81`、本机清单 `21`、升学规划 `27`、全栈路线 `28`、命名偏好 `29`、历史搬运件 `30`、复核与巡检清单（**以上是本机编号，包里这些全不发**） |

**原则：个人偏好不进包。** 发出去的是「空壳」——协议、检索、备份、打包、片段层，加两个空槽位（身份 / 日常）和三张空表（变更日志 / 重复问题台账 / 待确认）；口味、兴趣、学习线、升学规划、节律，都是收到包的人自己长出来的模块。

**许可（2026-10-19）**：根目录 `LICENSE` 是 MIT（Copyright © 2026 <你的账号>），随包一起发，别加进 `excludeFiles`。协议管的是代码与骨架、**不管内容**——别人拿去装进去的偏好和背景是他自己的，这份许可不替内容背书。

## 个人信息类的判定（决定某个模块要不要改回 drop 时对照）

判定不靠记忆，靠**问题**：这条信息换个人还成立吗？

- 名字、年龄、学校、专业、城市、社交账号、邮箱 → 只对本人成立，`drop`
- 健康 / 情绪 / 睡眠 / 就医史 → 敏感，整份 `drop`
- 本机环境：用户名、盘符、绝对路径、硬件型号、IP → 占位符能救的救（`%USERPROFILE%` / `<笔记库>` / `<代码仓库>`），救不了的 `drop`
- 私有项目：仓库地址、远程名、进度快照、数据库结构 → 整份 `drop`；确要留就按 `config.pack.scrub` 加替换规则
- 账与用量：token、订阅、消费 → 整份 `drop`（别人机器上的账跟这个数没关系）
- 私人关系、称呼来历、旧事、说话方式、图库 → 整份 `drop`（人格不继承，口味不预设）
- **机制与教训：留。** 踩过的坑、架构决策、踩坑的修法属于框架本身，正是要发出去的部分

## 命令

```bash
python tools/pack.py                 # dist/user-memory-<版本>-<日期>.zip
python tools/pack.py --no-zip        # 只生成目录，先看一眼
python tools/pack.py --out /tmp/x.zip
python tools/pack.py --persona       # 额外带上人格目录 persona/（人格包）
```

只装了 PowerShell 的 Windows 机器：`pwsh -File tools\pack.ps1`（参数 `-NoZip` / `-Out`，行为一致）。

- 打包时会用 `config.example.json` 覆盖 `memory.config.json`，别人的机器上没有你的路径
- `CATALOG.md` 在包里重算一遍，`PACKINFO.txt` 记录哪些清了、哪些没发
- 路由表里指向 `drop` 模块的行会自动删掉（完整文件名和纯编号两种写法都认）；`SKILL.md` 里用 `<!-- dist:drop-begin -->` … `<!-- dist:drop-end -->` 包住的段落整段不进包，用来放「只对本机有意义」的速查内容

## 收到包的人怎么用

1. 解压到 `~/.agents/skills/user-memory/`（Windows 为 `%USERPROFILE%\.agents\skills\user-memory\`）
2. `python tools/setup.py --workspace "<自己的笔记库>"`（或 `pwsh -File setup.ps1 -Workspace "<自己的笔记库>"`）
3. 按 `distribute: blank` 的模块逐条填自己的事实，格式见 `_模板.md`
4. 想要回自己的成品库：把自己那份 zip 收好，包里永远不会覆盖你本机那份

## 别做的事

- 别手改**解压出来**的包，改了不会回流；想多留点就回自己本机的模块改 `distribute:` 再重新打一次
- 别把 `dist/` 提进版本库（`.gitignore` 已挡）
- 打包只按分类执行，不检查内容质量：发之前 `--no-zip` 生成一次，逐个打开保留的模块扫一遍——重点看 `keep` 模块的**引言与例子**，漏网的私人句子多半藏在那儿
- 别把 `--persona` 当成「多发一份私人语气库」，理由见 `92a-人格包分发`

## 片段层不进包（2026-10-19 加片段层之后）

- `fragments/` 是生成物，**不复制进压缩包**（`memory.config.json` 的 `pack.excludeDirs` 里已排除）；包里只有 `references/` 的 md
- 收包的人跑 `setup.ps1` 会自动执行 `frag.py build` 切出片段；手动补跑 `python tools\frag.py build`
- `tools/memdb.sqlite3`、`memory.config.json`、`dist/`、`archive/` 同样不进包；`CATALOG.md` 在包里重算，不手改
- 自查别只看本机：`frag.py lint` 全绿只说明**本机**库没问题，包里没带片段，验的仍是 md 正文
