# AGENTS骨架

> 换设备、新工作区、或者发给别人时读这个：工作区 `AGENTS.md` 的完整骨架，照它写，路径按当前设备核实过的填。

## 为什么要有一份骨架

- `<工作目录>\AGENTS.md` 不进 git、不在任何备份里，换设备后大概率不存在，**只能当场重建**；`SKILL.md` 里发现没有就直接建，不用问
- 它是**第一层分发**：宿主每轮把 `AGENTS.md` 整个注入，所以「大类表 + §8 硬塞层」等于不用检索也在场
- 骨架只是骨架，每一节都该按用户自己的习惯改；别把别人的口味原样抄进去

## 骨架正文（照抄到 `<工作目录>\AGENTS.md`，路径按实际改）

````text
# AGENTS.md（本地约定 · 不进 git）

> 主工作目录：<笔记库>（日记在 `日记/`）
> 这份由记忆模块的 `tools/setup.py`（或 `setup.ps1`）生成，之后按自己的习惯改。

## 0. 快速模式（用户以自定义触发词开头时）

- **整条记忆链全部跳过**：不跑 `memgit.py check`、不读 `SKILL.md` / 语气模块、不读日记、不检索不注入、不落盘。触发词只是开关标记，不当正文，别复述它。直接当普通任务答，能多快就多快。
- **退出条件只有两个**：① 用户说「记」「记住」「记一下」「存一下」「更新记忆」这类明确写入口令；② 用户问（已隐去）这类真要翻记忆的问题。这时才恢复正常链路，写入交专职 teammate 后台办，不站在前面等。
- **只影响当轮**：下一句不带触发词开头就自动回到正常流程，不用再喊「正常模式」。
- **快不等于瞎答**：不知道就说不知道，不为了快编一个。
- **第二用途：Lead 给子智能体派活时也套同一个前缀（2026-10-24 用户定的）**：Lead 下发任务给 `memo` / `auditor` / 任何子智能体时，**prompt 第一行写成 `<你的名字或 ID>：<任务>`**，作用有两件：① 子智能体跳过整条记忆链（不跑 `memgit.py check`、不读 `SKILL.md` / 语气模块、不检索不注入、不落盘记忆）；② 执行风格**死板（rigid）**——严格照字面执行，只做任务里写明的项，不自由发挥、不自行扩写口径、不顺手改别的东西、不猜意图；拿不准就停下报「无法确认」，不许自己选一个做。理由：子智能体加载记忆既慢又会带偏口径、还容易自作主张扩写，用户要的是「照着清单一条条做，做完交判据」。原话（已隐去）

## 1. 开场三件事

1. **先对 git 最新**：`python ~/.agents/skills/user-memory/tools/memgit.py check`——只打一行 `GIT:`：已是最新 / 落后（自动拉）/ 本地领先（还没推）/ 分叉 / 离线没比成。**每次新对话第一件事就是它**，没对过别读记忆。**没反应就用本地**（fetch 3 s、pull 5 s 封顶，超时即按离线处理），别为了等云端把会话拖住，之后重载再对一次
2. 先读记忆入口：`~/.agents/skills/user-memory/SKILL.md`（Windows 为 `%USERPROFILE%\.agents\skills\user-memory\SKILL.md`），主文件 + 路由表；语气模块（若自建，默认 `references/89-语气与交流（每次必读）.md`）每次必读
3. **开场先跑一次语气包**：`python ~/.agents/skills/user-memory/tools/frag.py morning`——挑几片投进上下文，别复述内容
4. 日记：**只读最近 2～3 天**，另外**随机抽 1～2 篇更早的**当回顾——不要 glob 整个目录再逐篇读
5. **默认不读项目代码和项目大纲**：只在明确要求、或确有必要时读；真要读先定位再分段
6. 涉及现状（版本、路径、进度、硬件状态）：先核实，记忆里的都是历史线索，不把"曾经"当"现在"
7. **`memgit.py check` 单独先发**（网络好约 2 s，最多 3 s；等不到就当离线按本地读），其余读取**必须在同一条消息里并行发完**；禁止开局顺手跑体检、`memdb index`、重建定时这类维护动作

## 2. 文件红线（最高优先级）

- 未经明确允许，不改任何文件：笔记库、代码仓库、其他 笔记软件 笔记
- "修改"包含新建、编辑、重命名、移动、删除、批量整理；要动文件先说明计划和影响，得到同意再执行
- 只读操作（浏览、搜索、grep、读取）不受限；环境允许写、审批被关掉，都不等于有授权

## 3. 输出风格

- 简体中文；先给结论再解释；不默认贴代码块，不默认生成笔记
- 编程问题先讲原理和执行流程，留出自己动手的空间，别提前把完整解法剧透掉
- 明确要笔记时才做，按 笔记软件 卡片格式：外层四反引号 `text`、内部三反引号、frontmatter 顺序 `title`/`tags`/`date`、正文句末不加句号

## 4. 省 token 与缓存纪律

- 日记按第 1 节第 2 条读，别整目录扫
- 上下文只追加、不改写历史；别把每轮变化的内容塞进前缀
- 读文件先 `glob` / `grep` 定位，再按 `offset`/`limit` 分段读；同一文件不重复读
- 大批量检索、跨文件审计交给子会话，主会话只收结论；一次消息里并行发互不依赖的调用

## 5. 记忆更新

- 说"记住 / 记一下 / 更新记忆"时：按 `user-memory` 的写入协议写进对应模块，并在 `变更日志.md` 补一行
- 写记忆静默落盘，不复述改了什么
- 给子智能体 / 外部模型写提示词时**不注入**语气模块的人格设定，只带任务相关内容

## 6. 项目速览（只在碰代码时才用）

- 代码仓库：<代码仓库>，结构按实际填（如 `client` / `server` / `database`）
- 当前阶段：以项目大纲为准——**需要用的时候再去读**
- 构建 / 运行命令不确定时，先看 `README.md`、`package.json`、`pom.xml`，别凭印象猜
- 学习项目：优先自己写，AI 负责讲清原理、指出方向、帮忙验证

## 7. 自维护

**同一个问题第二次出现**（错误被指出两次、同一条纠正重复出现、同一个坑踩两遍）→ 直接在本节加一条一句话规则，带日期，不用问。计数与来历记在记忆模块 `82-重复问题台账`。

本节只放可执行、能自查的规则；超过 10 条就合并同类项，或把细则下放到对应的 skill。

- **查找轮次上限，超了就问用户**：① 记忆库类问题最多 3 轮——`frag.py auto/search` 一次 → 读命中模块 1～2 个 → `relates_to` 跳一跳，第 4 轮还没中就直接问；② 机器/环境类问题（路径、装没装、版本）最多 2 轮，且第 1 轮就把候选来源一次打全，没中就问；③ 先分清是「记忆库里的事」还是「这台机器上的事」——后者根本不走记忆检索。禁止为了命中率在原地反复试
````

## 三份 AGENTS.md 的固定位置（2026-10-22 用户点出来的，别再来回找）

原话（已隐去）。改规则时要同步的是这三份，**三份全在 git 里**，不是满盘搜：

| # | 角色 | 路径 | 进 git |
| --- | --- | --- | --- |
| ① | 框架（空壳起步版，给人用） | `%USERPROFILE%\.agents\skills\user-memory\templates\AGENTS.md` | **是** |
| ② | 笔记本 `<你的笔记本>` 完整版 | `%USERPROFILE%\.agents\skills\user-memory\templates\hosts\<你的笔记本>.md` | **是** |
| ③ | 台式 ITX `<你的名字或 ID>` 完整版 | `%USERPROFILE%\.agents\skills\user-memory\templates\hosts\<你的名字或 ID>.md` | **是** |
- **`%USERNAME%` 这个位是给 Arch 那台的（2026-10-22 用户定的「留着吧，以后有用」）**：三台的对应是 台式 Windows = `<你的名字或 ID>`、笔记本 = `<你的笔记本>`、Arch Linux = `%USERNAME%`；`%USERNAME%` 目前没有快照文件，等那台接入时 `--save` 补上，别拿它当台式那份的名字

- 工作区 `AGENTS.md`（`<paths.workspace>\AGENTS.md`）是**派生层**，不再当源改：它永远等于 `templates/hosts/<本机主机名>.md` 铺下去的结果
- 改规则的正确做法：三份一起改（①②③）→ `python tools/agents_hosts.py` 把本机那份铺到工作区 → 提交推送；换机器时 `memgit.py check` 拉完照样跑一次 `agents_hosts.py`，散文规则（§1～§7）也就跟着过去了，不用手搬
- **新设备第一次接入**：先在本机工作区写好 `AGENTS.md`，跑 `python tools/agents_hosts.py --save` 存成 `templates/hosts/<主机名>.md` 并提交——用户定的规矩「每次新设备都备份一份到记忆库」（2026-10-22）
- 脚本在 `tools/agents_hosts.py`：无参数=铺到工作区（无差异不写）、`--dry` 只报差异、`--save` 反向存回、`--list` 列出已有主机并标出本机
- `tools/agents_sync.py` 仍负责托管块（§8 硬塞层 + 记忆大类表）：真源是 `86` §七与 `tools/routes.py`，跑一次原地替换块内内容、块外一字不动
- **§0 快速模式也是骨架的一部分（2026-10-22）**：改骨架必须同步 §0（本模块骨架正文 + `templates/AGENTS.md` + `templates/hosts/<你的笔记本>.md` + `templates/hosts/<你的名字或 ID>.md` 四份一起），否则 `setup` 重生成工作区 `AGENTS.md` 时会把这节冲掉；`agents_sync.py` 只重写 CORE / ROUTES 两个托管块，管不到 §0
- **`setup.py --force-agents` 有保险了（2026-10-22）**：`write_agents()` 里加了 `host_snapshot()` 判断——目标 `AGENTS.md` 已存在、且 `templates/hosts/<本机主机名>.md` 也在，就直接跳过并打印「已有本机完整版 …，--force-agents 不覆盖；真要重来请先删 hosts 里那份，或直接跑 `tools/agents_hosts.py` 重新铺一遍」。原因：`templates/AGENTS.md` 只有 81 行空壳，hosts 版是 134 行完整版，一次 `--force-agents` 就能把本机 §0 + §7 那十几条规矩冲干净。字符串与主机名大小写无关（`p.stem.lower() == cur.lower()`）

## 骨架文件放在哪

- 本模块就是骨架的**权威版本**；`templates/AGENTS.md` 是随包分发的起步模板，给还没建过 `AGENTS.md` 的人一次性铺好
- 两份别写歪：改骨架先改本模块，再把 `templates/AGENTS.md` 同步成「公开起步版」
- 本机那份 `<工作目录>\AGENTS.md` 是用户自己的运行副本，**不进 git、不进包**；但它对应的快照 `templates/hosts/<主机名>.md` 进 git（上面 ②③），丢了大不了从快照重新铺一遍
