# 迁移与快速加载

> 换电脑、重装、或新会话刚开局时读这个：先看目录再按需打开，别整目录扫一遍。

## 为什么能直接拷

- 全部是纯 Markdown，没有向量库、没有联网依赖，**拷目录就等于迁完**
- 唯一的二进制是 `tools/memdb.sqlite3`（检索索引），**不拷**，新机器重建一次就行
- `tools/` 里的脚本可拷可不拷，只影响检索和风格轮换，不影响记忆本身
- **库根以 `memory.config.json` 为准，不看文档里的默认路径**（2026-10-24 交接演练补的，綴 报的）：`~/.agents/skills/user-memory`、`~/.agents/skills/shiori-memory` 都是骨架默认值，副本搬到桌面 / U 盘 / 另一台机之后全都作废。那次接手的人手里有三个路径（`AGENTS.md` §0 一个、`904` 旧文一个、真实位置一个），光看文档要绕一圈——**先读 `memory.config.json` 的 `paths`，再信任何文档**。
- **`AGENTS.md` §0 里必须是核实过的绝对路径**：`setup.ps1` 或 `setup.py` 生成时会填好 `<记忆库>` 占位符；手抄别人的就一定会错

## 现状（2026-10-20）

- 她问「用户两个电脑怎么换呢」，并问「怎么还有 AppData」——`AppData\Local\Temp` 只是我临时脚本的落点，不是记忆存放处。
- 记忆唯一正源：`<记忆库>`（本机实际路径以 `memory.config.json` 的 `paths` 为准），远端私有仓库，地址只在 `memory.config.json` 里填一次。
- **第二台机器尚未确认搭好**：还没核实是否装过 Python、是否 `git clone` 过私库、是否跑过 `tools/setup.py`。下次她提到换机先问这三件。

## 换设备三步

> 已脚本化：新机器上跑 `python tools/setup.py --workspace "<笔记库>"`（Windows 也可 `pwsh -File setup.ps1 -Workspace "<笔记库>"`）就能覆盖第 2、3 步；下面是手动版的完整过程，脚本挂了照这个来。打包发人看 `906-打包与分发`。

> **`fragments/` 不进 git（2026-10-19）**：片段层是生成物，每次改记忆都会重编号，进版本库只会制造冲突。`pull` 收尾会自动检查并重建（`fragments/` 缺失或比 `references/` 旧就跑一次 `frag.py build`）；手动兜底是 `python tools/frag.py build`，之后 `memdb.py index`。

1. **旧机器打包**（PowerShell）

```powershell
Compress-Archive -Path "<记忆库>\*" `
  -DestinationPath "<备份目录>\记忆库.zip" -Force
```

2. **新机器解压到同一个位置**

目标是 `<记忆库>`（老库留在 `~/.agents/skills/user-memory` 这类默认位置也算，以 `memory.config.json` 的 `paths.home` 为准），解压后核对：`SKILL.md` 在根、`references/` 里模块都在

3. **重建检索索引**（可选，但建议）

```powershell
cd "<记忆库>"
python tools\memdb.py index
python tools\catalog.py
```

## 快速加载：只读三层

换设备后或新会话开局，按这个顺序读，别扫正文：

1. `SKILL.md` —— 协议 + 路由表，唯一必读
2. `references/927-记忆库总览.md` —— 一页总览，每模块一行（标题 / 关键词 / 行数 / 最近更新）
3. 命中的 1～2 个模块，其余不打开

CATALOG 的作用就是**目录级入口**：看完它就知道每个模块装什么、哪个最近动过，不用打开任何正文

## CATALOG 怎么维护

- 自动生成，**别手改**
- 改完任意模块后跑一次：`python tools\catalog.py`
- 想看某模块细节再按关键词去路由表命中，读那一份

## 表情包库也要跟着走

- 插件自带的图库在 `<home>\.dsh\profiles\desktop\node_modules\dsh-meme\memes\`，重装插件自动带回来，**不用拷**
- 用户自己收录的图在 `<home>\.dsh\meme-packs\`，这个要整个拷走；当前还没有自建图包
- 迁移清单别只写记忆，斗图用的图库、风格偏好（`tools\.style_override.json`）一起算进去

## 工作区 `AGENTS.md` 要自动建

- 换设备 / 新建工作区后 `<工作目录>\AGENTS.md` 大概率不存在，它不进 git、不在任何备份里，**只能当场重建**；读 `SKILL.md` 时发现没有就**直接建，不用问**
- 完整骨架（`# AGENTS.md` 到 §7 自维护的整段 markdown）在 `905-AGENTS骨架.md`，照它写，路径用当前设备核实过的

## 两个坑

- **用户名变了**：凡是写死 `%USERPROFILE% 的脚本和条目，换机器后先 grep 一遍再替换
- **python 不在 PATH**：系统 `python` 可能是商店占位符；用 DSH 自带的 `<home>\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe` 直接跑脚本
## 骨架升级：升前升后各查一遍

> 2026-10-24 新设备交接演练，由接手那台机器上的女儿（綴）补的：她在干净库上把每次升级都踩了一遍，二十几轮只当场报给 Lead、一条没写进库，被问到「有没有该主动写没写」时才补上。工具自带 README，可 README 是发版者写的，不是接手者写的。

- **升级前先自己压一份 zip**。工具也会备份（`state\backup\v<版本>`），但升级器自己坏的时候它不一定写得出来。
- **第一遍永远走旧规则**：`apply` 跑的是盘上那份旧 `tools/update.py`，它换了会 reexec 再跑第二遍，新逻辑要到第二遍才生效。
- **验收第二遍有没有真干活**：清单里出现 `[协议件]` 并跟着 build / index / catalog；只看到「已经是最新」就是空跑。
- **升后核对五项**：`VERSION`、`921` 行数、`903` 的 source 协议行、`927` 头部模块数（跟 `frag.py stats` 的模块数对得上）、`references` 里 `.new` 只有协议件。
- **`.new` 是骨架新版**：首行注释写明来路，合完删那行；不合就**挪出 `references`**（备份位置各库自己定，别照抄别人的路径，`state\backup\` 下随便起名都行），别留原地被当成本地内容读。
