# 记忆自动注入（recall 引擎）

## 一句话

不再靠我"想起来去翻记忆"：宿主每轮钩一次 `recall.py`，它自己判断这一轮该不该把记忆塞进上下文。

> **DSH 那条通道怎么接、怎么验收、验收上栽过哪些坑，全在 `98-hook通道与验收.md`**（2026-10-20 拆出去）。本文只管引擎本身。

## 结构

- 引擎（唯一真相）：`<home>\.agents\skills\user-memory\tools\recall.py`
- 安装器（幂等）：`tools/install_hooks.py`，写 Codex/OpenCode 两份壳，`--print-dsh` 打印 DSH 段
- 状态（会自毁）：`%TEMP%\memory-recall\<session>.json`，Linux 走 `$XDG_RUNTIME_DIR` 或 `/tmp`

宿主只负责"每轮把用户那句话喂进来"，其余判断全在引擎里，所以换宿主不用改逻辑。

## 闸门（决定注不注入）

| 条件 | 行为 |
| --- | --- |
| 会话第一轮 | 不注入（AGENTS.md 已经常驻） |
| 轮次 % `MEMORY_RECALL_EVERY`（默认 1） != 0 | 不注入 |
| 出现回忆词（记得 / 之前 / 上次 / 我说过…） | 立刻注入 |
| 出现切换词（换个 / 另外 / 对了…） | 立刻注入 |
| 最高分 < `MEMORY_RECALL_MIN_SCORE`（0.2） | 不注入 |
| 低于榜首 35% 的条目 | 丢弃 |
| 同一 doc 超过 2 条 | 截断 |
| 总条数超过 `MEMORY_RECALL_MAX`（5） | 截断 |
| 命中 `sensitive=1` 的 10 / 22 | 永不注入 |
| 本会话已注入过的指纹 | 跳过 |
| `MEMORY_RECALL_OFF=1` | 全局关掉 |

**排序引擎（2026-10-21 换过）**：`retrieve()` 现在是 **frag 排模块 + memdb 取行**——
`_frag_module_ranking()` 用片段层的 BM25（含同义扩展、模块标题 ×1.0、模块 keywords ×0.8）决定该读哪几个模块，
`_best_line_for()` 回 `memdb.sqlite3` 里给每个模块挑**一行**代表（按命中词的稀有度 `1/(df+1)^0.6` 加权，
常见词「写入」赢不过全库唯一的「沙箱」）。原来这条路径直接拿 `memdb.search_rows` 排模块，
那是行级字面匹配、没有同义扩展也没有模块加权，同一批查询 `recall@1` 只有 5/22，frag 是 20/22。

**靠 keywords 蹭上来的模块会被压下去**：模块分里有 `module_kw ×0.8`，而 frontmatter 的 keywords
可能和正文脱节。实测过一次（2026-10-21）：给 `08-环境与硬件.md` 加了 `代理`/`TLS`/`握手`/`proxy`
这批词，那一篇正文里一个都没有，于是「代理又连不上了」被它抢到榜首，真正写这事的 `82:30` 反被挤掉。
所以取到行之后再看**这一行有没有字面命中**，0 命中的只保留 0.25 底分。

**「有没有字面命中」必须是第一排序位（2026-10-21 补）**：稀有度权重 `1/(df+1)^0.6` 会把命中分压得很低
（常见词权重只有 0.084，命中两个词才 2.9 上下），而 `importance` 高的 0 命中行光靠 `imp*2 = 6` 就能赢，
全库因此有 31 个模块「明明有命中行却挑了 0 命中行」。排序键 `_best_line_for()` 改成分层比较
`key = (1 if hits else 0, s, -line)`：先比有没有命中，再比大小，最后按行号。线上 `recall@1` 77.3%→86.4%、
`@3` 86.4%→95.5%，4 条变好 0 条变坏。同一天还把 `BANNED_HINTS` 里的一个机制词撤了（它命中全库 25 行，
0 行在 `10`），因为一条排错类问题本该命中 `83:5`，却因那行含这个词被整行丢弃。**改这张表前先 grep 命中分布。**

> ⚠️ 写检索经验时**不许出现任何一条评测题的实词**，模块号可以写。第三次踩：照抄实词后题和答案同现，
> 那批查询开始命中说明文档，`recall@1` 当场掉 9 点。

**写 keywords 的规矩（同一天立的）**：一个词要么它真出现在自己正文里，要么它是这个词在她嘴里的**另一种说法**
且这个模块确实是那个话题的正主。两者都不满足就是拿索引下毒。没做自动检查——试过「keywords 必须在自己正文出现」
（82 条误报，「低谷」「崩溃」这类别名本来就该写）和「不在自己正文却在别的模块正文 = 越界」（46 条误报，
`语气`/`人格`/`风格` 这些词本来就在二十来个模块里正常共现），两条都筛不出真问题，删了，只留规矩。

**`MEMORY_RECALL_EVERY` 默认从 4 改成 1（2026-10-20 她要求）**：她原话「提醒有记忆库这个东西的存在就行，但是 agent 它压根就不会读，说好的每次都读呢」——现在是每轮都注入，卡头固定带一行 `POINTER`（记忆库路径 + 跑 `memread.py` 的口诀），无相关内容时也至少注入这一行。

## 三家宿主怎么挂

- **Codex**：`<home>\.codex\hooks.json` 的 `UserPromptSubmit` 跑 `python recall.py hook --host codex`，输出 `{"hookSpecificOutput":{"hookEventName":"UserPromptSubmit","additionalContext":"..."}}`。
- **DSH**：`@deepseek-ai/dsh-hooks-codex` 读同一份 `hooks.json`，加 `cordis.patch.yml` 里的 insert 段；**两个病根（沙箱模式、引号写法）、重启与重载、验收命令全部见 `98`**。
- **OpenCode**：`<home>\.config\opencode\plugins\memory-recall.js`，`chat.message` 记最后一句、`experimental.chat.system.transform` 把块 push 进 `output.system`。

## 验收

只认一条命令：`python tools\hookcheck.py [--session <id>]`，退出码 **0 = 四件齐 / 2 = 通道通了但本轮没交付 / 1 = 通道不通**。四件是什么、判据怎么写、哪些字段**不能**当证据，见 `98` §2–§5。一句话口径：**通道通 ≠ 记忆进了上下文。**
> 外部同类插件的注入路径、缓存代价与召回公式见 `93a-外部同类插件调研`（2026-10-25）。

## 运维

```
python tools\recall.py text "随便一句话"   # 看会命中什么
python tools\recall.py stats               # 轮次 / 指纹数 / 闲置秒
python tools\recall.py reset               # 立刻清状态
```

- 关掉：`MEMORY_RECALL_OFF=1`，或删掉对应宿主壳。
- 回滚 DSH：`cordis.patch.yml.bak-memory-recall` 覆盖回去再重启。
- 每轮冷启动 100 ms 级，不需要常驻守护进程；状态文件到期自删，满足"会话结束 / 30 分钟无活动销毁"。

## system prompt 常驻段（未实现，2026-10-21 只写原理）

现在记忆提示走 `UserPromptSubmit`（对话流里的一条 user 消息），不进系统提示词。要常驻，DSH 的正规口子是 `ctx.systemPrompt.section({ name, order, text, complete? })`，返回 disposer，插件 fiber 一销毁就自动摘段，不用自己清。

- **去重**：同一作用域重名直接抛错；`agent.ctx` 注册的同名段对全局段是「遮蔽」不是重复，不用先删旧的。
- **排序**：段按 `order` 升序拼；约定 `-100` harness 身份、`0` 部署 persona、`100–199` 工具引导；同 order 按注册顺序破平（加载时序的产物，别依赖）。
- **别用 `complete: true`**：那是「整段替换系统提示词」，两个 effective complete 段会让组装失败。
- **段文本必须确定性**：`{{变量}}` 严格插值、缺值即抛；会变的东西走 `context()` 的运行时快照，不写进段。
- **缓存代价**：段每轮重复计费，段文本或顺序一变，KV cache 从第一个变化 token 起失效——常驻段只放几行固定元规则，按需条目继续走 hook；开关照 genui 先例存 settings（`promptEnabled`），**不 patch 第三方包**。

## 坑

- PowerShell 管道默认 GBK，中文 payload 必须按 utf-8-sig / utf-8 / gbk 依次试解码，否则静默不注入。
- `cmd` 的 AutoRun 与本机 PowerShell profile 都会打印 fastfetch，用 `shell=True` 自测会污染 stdout；DSH 的 shell 工具不带横幅。

## 待办（2026-10-20 收工前记）

- **闭环缺口**：通道已通（`exit=0`）但交付仍是 `0 字`，要等一次 `chars > 0` 才算真进上下文；这是明天第一件事。
