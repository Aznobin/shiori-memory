# 外部同类插件调研

## 外部同类插件调研（2026-10-25）

三个 DSH 插件都往上下文里塞东西，路径不同。

- `dsh-speak-up`：不查记忆。它只做 `agent.followup()`，往收件箱推一条 `source.kind=speak-up` 的 user 消息，让 DSH 自己走一轮；
  人格、历史、工具、记忆全照旧，包括本库的 hook。它只读会话标题和「距上次说话多久」（`ctx.sessionController.inspect`）。
  能替的是 schedule 定时任务，替不了 hook。
- `dsh-feiyu-mood`：`agent.ctx.systemPrompt.context()`，注入一段心情。同层，但注入的是心情不是记忆。
- `dsh-fish-memory`：真同类。Cordis 插件 + `systemPrompt.context()`，不走 hooks.json。

### 机制细节（2026-10-26 调研源码 `speakup_host.js`）

1. 定时器是死的：`ctx.interval(fn, 间隔分钟 * 60 * 1000)`，默认 30 分钟一次（`speakup_host.js:772`），改配置后下一轮自己换表。
2. 变的是每轮的「命中线」，不是间隔。
3. 三个接口：`ctx.interval`（Cordis 定时器服务）；`会话服务.inspect(sid)`（`:549`，判会话还活着、在不在干活、距她上次说话多久）；
   `agent.followup(message)`（`:728`，往活着的同一 agent 收件箱推一条消息，DSH 自己的 loop 认领并走一轮）。
4. 推的是 **user 消息**（`角色: 'user'`，`source.kind='speak-up'`），所以工具、人格、记忆全照常跑；`source.kind` 只给前端看。
5. 命中线公式：`最终命中线 = 档位命中线 × 时机因子 + min(加成上限, 连没中 × 没中加成)`，夹 0~100，掷到线以下才开口。
6. 档位命中线：峰时（周一到周五 9:00-12:00、14:00-18:00）20，谷时 60。
7. 时机因子：距她上次说话 < 20 分钟 → ×0.15；> 360 分钟 → ×1.5。
8. 没中加成：每没掷中一次 +10，上限 +40，掷中就清零。
9. 三道闸：安静时段 1:00-8:00；自己刚开口后 20 分钟冷却；默认开着的试运行（只记账不真发）。
10. 结论一句：外观上「间隔毫无规律」是「定时器固定 + 命中线随时机漂移」叠出来的错觉，不是随机定时。
11. 我们这边现状：主动开口走 `schedule` + 掷骰，只有 70/30 两个死数字，缺三样——距她多久没说话的因子、没中攒加成、自己刚开口的冷却。

### 两条注入路径的缓存代价（fish-memory 作者实测，见其 `lib/index.js:3630-3641`）

同一句短消息：

- 记忆关：未缓存 107 / 缓存读取 11392 → 0.001
- 用 `section` 注入：未缓存 12055 / 缓存读取 0 → 0.02（20 倍）

提示词只多 550 token，整段一万二的缓存全废。原因：`section` 拼进系统提示词，一变整段作废；
`context` 把内容当一条消息追加到对话末尾，只在内容真变了才追加（`dsh-agent-loop` 的 "only when the retained value differs"）。

`section` 另有个坑：`systemPrompt.section()` / `.context()` 返回的是 Cordis 的 effect disposer **函数**，
不是 `{ off() }` 对象；写成 `x.off()` 永远不成立，一次都卸不掉。

### fish-memory 的召回公式（值得抄）

```
P = C ×（基础 + 鲜活 + 重要 + 情绪）
C = 命中词的稀有度之和（IDF，按库自己的词频），不除以问句长度
```

门槛卡 `C`（证据）不卡 `P`（总分）：`P` 里有鲜活度，851 条里 833 条没时间戳，一压低整个库分数下移，门槛跟着动。

其他设计：jieba 词表分词（「车」不撞「车站」）；鲜活度 `2^(-天数/半衰期)`，事件 30 天、情绪 7 天；
长期事实不淡但最多占 2 个位置；「已被取代」和「提炼判跳过」不参与召回；证据弱就少给，不硬凑条数。

### 对本引擎的结论

现在 `recall.py` 是 BM25 + `score < max(0.2, 最高分*0.65)` 卡门，每篇最多 2 条，无时间衰减、无 IDF 稀有度。
升级优先两步：① 门槛换成 `C`（稀有度证据）而不是总分；② 注入从 hooks.json 的 Python 进程换到插件的 `systemPrompt.context()`。
