# 记忆骨架设计与九家插件对比

> 这份回答两件事：本库的骨架凭什么算「可移植、可升级」，以及九家 DSH 记忆插件里哪些机制值得吸收。只写结论和判据：机制现状看 `918`，注入通道看 `908`/`917`，旧的外部调研看 `909`。

## 1. 结论先行

- 三根柱子：**内容与骨架分离**（内容永不进升级清单）、**真源唯一且可重建**（Markdown 是唯一事实源，索引/片段/注入全是派生）、**接口与实现分离**（存储、检索、注入三层各自留适配位）。
- 现状不是从零开始：`manifest.json` + `tools/update.py` + `tools/skeleton_guard.py` + `tools/framework.py` 已经构成骨架替换协议雏形，缺的是**验收集、兼容层和接口层**，不是推倒重来。
- 九家没有一家能整体照搬：越像产品越绑死单个 SQLite、外部服务或宿主内部 API；能直接吸收的是**机制**——写入准入闸门、证据/秩融合、软删与冲突裁决、日志与派生分离、失败留凭证。
- 所以本设计只做加法：不动正文格式、不动编号分区、不动现有工具链，用适配器和验收集把骨架边界钉死。

## 2. 五层映射与接口

| 层 | 现状（真源？） | 对外接口（必须稳定） | 换实现时要保住的东西 |
| --- | --- | --- | --- |
| 事实层 | `references/`、`memory/`、`SKILL.md`、`templates/`、`tools/persona/`（**是**） | 模块号 + frontmatter 七字段 | 纯文本、人可读、git 可 diff |
| 片段层 | `fragments/` + `tools/frag.py`（否） | `build` / `lint` / `search` 三个子命令 | 幂等：同一正文连跑两次结果一致 |
| 索引层 | `tools/memdb.sqlite3` + `tools/memdb.py`（否） | `index` / `search`，输出带 `doc:line` | 可删可重建，删掉不影响事实层 |
| 注入层 | `tools/recall.py` / `memread.py` / hook（否） | 一次调用返回「该读哪几篇、哪几条」 | 通道通 ≠ 已交付，必须能自证（见 `917`） |
| 骨架层 | `tools/`（除 `private/`）、`templates/`、`900-999` 协议件、`VERSION`、`manifest.json` | 升级只走清单，内容一律不碰 | 清单外一个字节不动 |

接口层判据（拟写进 `918` §4 不变量）：**任何一层的实现被替换，上一层文件不需要改一个字**；做不到就说明接口没抽干净。

## 3. 四张数据契约

1. **内容契约**：模块号在 `memory/` 或 `references/`，末位为 0 的是骨架槽位、其余是内容；frontmatter 七字段不齐即硬错误。
2. **清单契约**：`manifest.json` 只列骨架文件（含 `sha256`、`version`、`min_python`），自己是唯一不写进自己的文件；升级只动它列的东西。
3. **召回契约**：一次检索必须能回答「命中哪一条、为什么命中、证据有多强」；`doc:line` 是唯一身份证，缺它不算命中。
4. **写入契约**：一条记忆走「归属模块 → 去重 → 状态变更 → 日期锚点 → 冲突登记」五道门，落盘后必须回读命中（`918` §4.9）。

## 4. 三层适配：可移植性怎么落地

- **存储适配**：默认纯 Markdown（现状即最优，零外部依赖）；SQLite 索引只作加速件，可选可删可重建；向量库只做插件式附加层，不能成为唯一检索通路。
- **检索适配**：规则 / BM25 通路永远保留为**降级路径**，没模型、没网络、没向量库也能出结果；外部语义检索只加分，不抢唯一入口。
- **注入适配**：hook 只是**其中一种**入口，`SKILL.md` 的三步读法（总览 → 命中模块 → 回读）必须能脱离 hook 独立工作；判据：拔网络、拔向量库、换一个不认 hook 的宿主，读记忆仍走得通。

## 5. 升级流程六步与四个状态

六步：冻结 → 备份 → 替换 → 重建 → 验收 → 回滚点记录。

| 状态 | 触发条件 | 必须做的动作 |
| --- | --- | --- |
| 已是最新 | 远端版本 = 本地版本 | 什么都不做，静默退出 |
| 可升级 | 远端版本更高、`min_python` 满足 | 打快照后只替换清单内文件，冲突文件落 `.new`，不静默覆盖 |
| 需先升级骨架 | 内容引用了新协议件、旧骨架不认识 | 先换骨架，再跑内容兼容检查 |
| 不可升级 | `min_python` 不满足 / 清单缺失 / 隐私门命中 | 停手并明确报原因，不许「先跑了再说」 |

红线：备份先于替换、清单外不动、失败留 `.new`、`--dry` 先看清单。

## 6. 九家插件对比

| 插件 | 记忆层级 / 存储 | 写入与召回时机 | 对骨架的价值 |
| --- | --- | --- | --- |
| `hindsight#coding-agents` 0.8.2 | 插件不存记忆，全在 Hindsight 服务端；本地只有 tmpdir 会话态与 usage.jsonl | 每步 pre-step 注入、turn-stopping 写回，无客户端节流 | 借鉴「注入进 user 消息不进系统提示词」「按历史末块判重」「只报数量逼出检索」；不抄外部服务依赖 |
| `dsh-mnemon` 0.5.35 | `~/.mnemon` 下 `runtime/memories.json` 是唯一事实源，`USER.md`/`MEMORY.md` 只是投影 | 默认 guided：模型显式调用且拿到 receipt 才算写入；30s idleReview 归纳；检索按需调工具、默认关 embedding | 借鉴 receipt 闸门、单文件真源 + 投影、tmp/rename + commit marker、optInOnly fail-closed；不抄 30+ 子包体量 |
| `OpenViking#…/dsh-memory-plugin` 0.5.29 | 记忆按事件日志存、页面视图是派生；本体依赖外部 OpenViking 服务 | MCP `remember` 走服务端短会话、不绑定当前会话；URI 守卫拦外泄 | 只借鉴「日志与派生分离」；外部服务依赖整条不抄 |
| `dsh-prime-memory` 0.26.11 | JSONL 事实源 + `memory.db` 检索库双写；L0 原始层即时落盘，L1/L2/L3 异步蒸馏 | 每条新用户输入前 pre-step 召回；keyword/embedding/hybrid + RRF(k=60)；冲突默认冻结关闭 + 人工裁决 | 借鉴「原始层即时落盘、派生层慢慢算」、canonical cwd 作工作区键、成本按 provider/model 记账 |
| `dsh-tiddlywiki` 0.34.0 | TiddlyWiki 文件夹形态，自述不是记忆插件、不后台抓取；多 wiki farm + 内置 git 自动提交 | 工具按需调用；写路径一律先读后写 + 乐观并发双令牌、软删进回收站；搜索先本项目、0 条才扩全库 | 借鉴「纯文件即持久层」「回执写明实际搜索范围」；不抄把语料与工作笔记混一库 |
| `dsh-auto-memory` 3.3.17 | 三层 Markdown（用户级 / 项目 MEMORY.md / 每日 append-only 日志）+ 白板 + 交接账本 | turn-stopping 自动沉淀、寒暄轮跳过；attr/keyword/dense/lex 多臂 **rank-space RRF k=60**；注入预算默认 8000 字符 | 最接近我们的自动记忆：借鉴秩空间融合、水位触发的交接、迁移包带版本 + sha256 + 上限 |
| `memory-eternal` 0.17.0 | 单库 SQLite（WAL）+ Markdown 双向镜像；M 张卡片表与隔离表分离 | turn-stopping 按会话事件 seq 增量捕获；`enforceAudit` 决定落主表还是隔离表，状态变更一律写 audit_log | 借鉴「写库前的准入裁决」与唯一状态入口；不抄单库黑盒 |
| `mneme#dsh-mneme` 0.9.4 | SQLite WAL；`conflict_pending`、`receipt_chain`、`dream_runs` 分表 | 显式 scope + 会话写入预算；空闲自动巩固（默认开）；冲突冻结默认关、人工裁决；每轮产出 snapshotHash 收据 | 借鉴空闲巩固节律与可验收据；不抄「未标注即全局」的宽松 scope |
| `dsh-fish-memory` | 插件内存储 + `systemPrompt.context()` 注入（旧调研 `909`） | 每轮检索、命中才注入；召回分 = 稀有度证据 ×（基础 + 鲜活 + 重要 + 情绪） | 召回公式与「门槛卡证据不卡总分」已记在 `909` |

## 7. 借鉴清单与明确不抄

**吸收（九条，按价值排序）**

1. **缓存纪律分两档**：静态纪律进系统提示词固定段（字节稳定），动态记忆走会话尾部追加，内容没变不重复注入（`dsh-auto-memory`、`hindsight`）。
2. **多臂融合用秩空间 RRF(k=60)**，别在分数空间加权：候选增删只平移秩，不破坏既有相对序（`dsh-auto-memory`、`dsh-prime-memory`）。
3. **写库前准入裁决 + 唯一状态入口**：能不能落主库由守卫裁决，状态一变就写审计（`memory-eternal`）。
4. **写入要 receipt 才算成立**，读改先读后写 + 乐观并发令牌，删走软删回收站（`dsh-mnemon`、`dsh-tiddlywiki`）。
5. **原始层即时落盘、派生层慢算**：慢 LLM 只影响派生层，绝不让蒸馏阻塞或丢原文（`dsh-prime-memory`）。
6. **冲突冻结默认关 + 人工裁决 + 盖章审计**：机器判不了的停进待裁决区，别让机器判错覆盖（`mneme`、`dsh-prime-memory`）。
7. **每次后台运行产出机器可验收据**（snapshotHash + receipt 链），失败轮不许写假 ok（`mneme`）。
8. **迁移包自带格式版本、校验和算法版本与文件/体积上限**（`dsh-auto-memory`）。
9. **工作区标识用规范化纯字符串 cwd**，同步可得、不做 I/O、never-throw；取「过度隔离优于泄漏」；**只报记忆数量不报目录**，逼出真正的检索（`dsh-prime-memory`、`hindsight`）。

**不抄（四条）**

1. 依赖外部记忆服务 / 云端 token：离线即无记忆，数据 schema 还不在自己手里（`hindsight`、`OpenViking`）。
2. 单库黑盒或巨型单文件插件：人不可读、git 不可 diff、审计与迁移成本高（`memory-eternal`、`dsh-auto-memory` 的 2.1 万行单文件）。
3. 自动写入无闸门、无审计：一条错记忆比没有记忆更贵。
4. 「未标注即全局」的宽松隔离、把语料与工作笔记塞同一库：前者会泄漏，后者要靠拆库而不是调参解决（`mneme`、`dsh-tiddlywiki`）。

## 8. 与现状差距 + 落地顺序与验收判据

| 顺序 | 动作 | 验收判据 |
| --- | --- | --- |
| 1 | 接口层固化：本文件与 `918` §4 登记五层接口 | 两层文档口径一致，改动能落到具体层 |
| 2 | 升级验收集：一条命令跑清单校验 + 体检 + 检索回读 | 全绿；失败打印真实原因，不静默跳过 |
| 3 | 降级读取路径：不依赖 hook 的三步读法写进 `SKILL.md` | 关掉 hook 仍能命中同一模块 |
| 4 | 召回升级：证据闸 + 鲜活度 + 稀有度权重 | 评测 22 题命中率不回落（`915`） |
| 5 | 空闲巩固：候选合并 + 索引重建交给 `memo` | 低频时段可跑，对话零延迟 |

## 9. 来源与证据等级

- 九家结论取自 2026-10-27 三个只读侦察会话：包清单走 `https://data.jsdelivr.com/v1/packages/npm/<pkg>@<ver>?structure=flat`，单文件走 `https://cdn.jsdelivr.net/npm/<pkg>@<ver>/<path>`；Hindsight 与 Mnemon 另有对应 GitHub 提交工作树的行号证据（npm 包内无 `.ts` 实现，CDN 复现不了行号）。
- 版本：`hindsight-coding-agents@0.8.2`、`dsh-mnemon@0.5.35`、`OpenViking dsh-memory-plugin@0.5.29`、`dsh-prime-memory@0.26.11`、`dsh-tiddlywiki@0.34.0`、`dsh-auto-memory@3.3.17`、`memory-eternal@0.17.0`、`dsh-mneme@0.9.4`。
- 证据等级：带 `文件:行号` 的是源码，`package.json` 的 engines/权限/依赖是包元数据，标注 README 的只是自述，市场简介只用来选包不当结论。自述与源码不符已按源码纠正：auto-memory 实有 14 个 `memory_*`、prime-memory 实注册 20+、tiddlywiki 实为 17 个、mneme 冲突冻结**默认关**。
- 未确认（停在原地不猜）：Hindsight 服务端打分与遗忘机制、`mneme`/`prime-memory` 的权限标签、tiddlywiki 的 tiddler 级落盘切分。
