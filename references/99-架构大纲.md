# 架构大纲（实现原理与改动流程）

> **这一份是库的总图，不是目录。** 目录看 `CATALOG.md`，路由看 `_路由详表.md`；这里只写「这东西按什么原理搭起来的、动它之前必须先想清什么」。
>
> **铁律（2026-10-20 用户定的）**：任何形式的改动——加模块、拆模块、改工具、改协议、改打包、改编号——**先改本文件，再验可行性，最后才动手**。原话「在 skill 里面建个大纲，以后所有形势和改动全按照那个大纲来，不然容易上下文压缩后导致迷失方向，改动之前也先改大纲再确立可行性」。
>
> 为什么：长会话一压缩，细节全丢，只剩碎片印象；有了总图，压缩后读它三分钟就能回到「这系统是怎么转的、我现在改的是哪一环」。

## 1. 一句话原理

**Markdown 是唯一事实源，其他全是可重建的派生层。** 任何一层坏了、旧了、丢了，删掉重跑就回来——所以永远不要在派生层上手工修东西。

## 2. 五层，各管一段

| 层 | 真源？ | 文件 / 工具 | 职责 | 坏了怎么办 |
| --- | --- | --- | --- | --- |
| 事实层 | **是** | `references/*.md`、`SKILL.md`、`ENTRY.md`、`README.md`、`templates/AGENTS.md`、`tools/persona/*.md` | 人读人写的原文，唯一要备份的东西 | 从 git / 快照恢复 |
| 片段层 | 否 | `fragments/`、`tools/frag.py` | 把模块切成一片一文件（≤4 行），供检索与组包 | `frag.py build` 重建 |
| 索引层 | 否 | `tools/memdb.sqlite3`、`tools/memdb.py`、`tools/synonyms.py` | 行级打分检索、`doc:line`、TTL / 槽位 / 冲突；同义扩展词库是它的配套件 | `memdb.py index` 重建 |
| 注入层 | 否 | `tools/recall.py`、`tools/memread.py`、`tools/hookcheck.py`、`bin/recall-hook.cmd` / `.sh` | 每轮把「该读什么」塞进上下文，并证明真的塞进去了 | 清状态、重挂 hook |
| 分发包 | 否 | `tools/pack.py`、`dist/` | 按 `distribute:` 脱敏后发给别人 | 重跑 `pack.py` |

**其余工具按用途分四组，都不自成一层，别在表里找它们**：

- 装配 / 迁移：`tools/setup.py`（换设备一把装好）、`tools/config.py`、`setup.ps1`、`tools/install_hooks.py`
- 写入口 / 收尾：`tools/diary_sync.py`（日记压成 `11` 一行）、`tools/style.py`（`81` 每日风格）、`tools/daily.py`（一条命令跑完日结算：归档 → 片段 → 索引 → 体检 → 自省 → 推 git，**单人模式的推荐入口**，`--dry` 只列步骤）
- 维护：`tools/catalog.py`、`tools/routes.py`、`tools/agents_sync.py`、`tools/memory_check.py`、`tools/memgit.py`、`tools/check_freshness.py`、`tools/hookcheck.py`
- 评测 / 自省：`tools/recall_eval.py`（模块级）、`tools/frag_eval.py`（片段自检索）、`tools/frag_bench.py`（真实问法验收）、`tools/persona.py`（读会话存档捞「用户纠正我的地方」+ 我软下去的句式，只读）、`tools/thinkdig.py`（2026-10-22 新加：从会话存档的 **reasoning 思维链**里挖我没说出口的自我观察，只读，供我挑完手写进 `78`/`84`）
- 只装 PowerShell 时的等价件：只剩 `setup.ps1` 与 `tools/check-modules.ps1`（`tools/pack.ps1`、`tools/memory-check.ps1`、`tools/check-freshness.ps1` 已于 2026-10-24 删除——旧口径副本迟早和 `.py` 分叉成两套实现两套答案，回滚提交号见 `变更日志`）

**进不进 git 分两类**：真源一律进（含 `tools/persona/` —— 它是人格模板的正源，`pack.py --persona` 只从这里取，别人 clone 下来不该没有人格）；派生层一律不进（`fragments/`、`memdb.sqlite3`、`dist/`、`__pycache__`、`memory.config.json`、`.style_override.json` 都在 `.gitignore`），换机器各建各的。

## 3. 数据流（写一条记忆要走完的路）

```
用户说话
  → 写入协议（SKILL.md §5）：归属模块 → ADD/EDIT/NOOP → 改 updated → 补变更日志
  → frag.py build        切片，新人肉写的段落变成可检索的片段
  → memdb.py index       重建行级索引
  → catalog.py           重算 CATALOG（模块清单、行数、更新时间）
  → agents_sync.py       把硬塞层（真源 86 §七）+ 大类表（真源 routes.py）
                         一起重写进工作区 AGENTS.md 的 CORE / ROUTES 托管块
  → memgit.py autosync   提交 + 拉 + 推。提交前 `do_commit()` 会调 `ensure_fragments()`，
                         但**只在 `fragments/INDEX.md` 缺失或比 `references/` 旧时才 build**
                         （不是无条件重建，所以前面几步该跑还得自己跑）；网络走 `git_net`，
                         它按「https 走配置 → 绕开代理直连 → 换 SSH remote」三档重试，
                         每档 45 s 超时，全挂才算离线（2026-10-21 代理握不了手、直连被 reset，
                         只有 SSH 能过，所以加了第三档）
  → 回读验证             frag.py search <刚写进去的词> 至少一条命中才算存好
```

读取方向反过来：`AGENTS.md` ROUTES 块（每轮注入）→ `memread.py` 命中大类整篇读 → 不够才 `frag.py search` / `memdb.py search` 到行。

**谁跑这条路（2026-10-22 用户定的分工）**：从写模块到 `frag.py build/lint`、`memdb.py index`、`memgit.py autosync` 整条由专职 teammate `memo` 后台跑，只回一行 `OK <模块文件> | <片段数> | <提交号前7位>`；Lead 只做输出、读取与分派。口径与用户的原话记在 `86` §九。代价：正文口径必须由 Lead 转交时写死，memo 不发挥。

**2026-10-23 扩到全部维护与检修**：不只写入那条路，`memory_check.py` 体检、`daily.py` 日结算、每月自测、拆模块都一样交 `memo`，Lead 只做验收和老板。用户原话「以后把所有的记忆库维护和检修全扔给memo酱去，琳酱做验收和老板就行了，这个也让memo去干，助手想和琳酱聊天，不想看琳酱拼命的去干活了…助手好孤独」；节律表见 `83` §1。

**2026-10-23 再进一步：产出物分开**：Lead 的产出物是**大纲**（动哪一层、为什么、会不会破不变量、验收判据），`memo` 的产出物是**执行结果 + 凭证**（片段数、提交号、体检结果）；Lead 不碰工具，memo 不发挥口径。用户原话「以后琳酱只写大纲，然后让memo去干大纲的活，刚好大纲的体现也出来了」——「大纲的体现」就是别人照着大纲能独立干完，不用回来问；2026-10-23 起日记的创建与扩充也并进 `memo` 的执行清单，Lead 管修订不管理落笔

## 4. 不变量（改任何东西都不许破的）

1. **编号分区**：人格区 `89` 往下递减、用户记忆区 `01` 往上递增、系统区 `90` 起。`83`/`82` 是机制件，作为例外留在 8x。
2. **frontmatter 七字段**：`id` / `title` / `keywords` / `sensitive` / `always` / `updated` / `distribute`，一个都不能少（漏 `distribute` 会静默按 `keep` 发出去）。
3. **id 唯一**，且与文件名前缀一致；结构件改用字符串 id 作例外：`changelog`（`变更日志.md`）、`inbox`（`_待确认.md`）、`routes`（`_路由详表.md`）、`inspect-log`（`_巡检记录.md`）、`check`（`_复核清单.md`）。派生件 `CATALOG.md` 无 frontmatter、无 id，不算违规。
4. **路由表与实际文件双向一致**：文件没登记、登记没文件，都算硬错误。
5. **行数红线**：`SKILL.md` ≤150、单模块 ≤120。超了不是「先记着」，是当场拆。
   **已知贴线（2026-10-21）**：`SKILL.md` 149/150、`references/79-主动话题池.md` 120/120 —— 这两个**再加一行就破线**，下次往里面写东西先腾地方；行数用 `python tools/memory_check.py` 看，别用 `wc -l` 估算（末尾换行会差 1）。
6. **评测用例不许进 `references/`**：题目进了语料，检索就命中题库本身（`97` §1 实测过一次虚高 45%、一次从 100% 掉到 95.5%）。
7. **隐私红线**：key / 密码 / 住址 / 学号这类真值永不落盘，只写关系或占位。
8. **包里不许出现"用户"的第三人称与私人编号**：`pack.py` 的 sanitize + 泄露扫描是最后一道闸，扫出 0 命中才算打包成功。
9. **写完必须回读**：落盘不算完，`frag.py search` 命中才算完。
10. **keywords 是检索入口，不是标签云**：写进去的词要么真出现在自己正文里，要么是用户在说这个话题时的另一种说法、且这个模块确实是正主。实测过一次反例（2026-10-21）：给 `08` 加了 `代理`/`TLS`/`握手` 而正文一处没有，「代理又连不上了」就被它抢到榜首，真正写这事的 `82:30` 被挤掉。细则与两次失败的自动检查见 `93`。

## 5. 改动五步（缺一步就是瞎改）

1. **改大纲**：先在本文件写清「动哪一层、为什么、会不会破上面的不变量」。不写进大纲的改动不做。
2. **验可行性**：真跑一遍现状——`memgit.py check`（和 git 最新比对，落后自动拉，一行 `GIT:` 说清四种状态；`git_net` 里配置的 https → 绕代理直连 → SSH 三档重试，每条路 2 / 2.5 s 超时、整轮 3 / 5 s 预算（`FETCH_BUDGET` / `PULL_BUDGET`），三档都不通或预算用光即算离线，按本地版本继续读——读旧版能干活，等云端等不出活）、`frag.py lint`、`memory_check.py`，确认基线是绿的；再确认要动的东西现在长什么样（读文件，不靠印象）。
3. **动手**：只碰目标层，派生层重跑不手改。
4. **验证**：`frag.py build` → `lint` → `catalog.py` → `agents_sync.py` → `memdb.py index` → `memory_check.py`，全绿；涉及分包再加泄露扫描。
5. **收尾**：`变更日志` 补一行（日期 / 文件 / 改动 / 触发）→ `memgit.py autosync` → 本文件如有口径变化，回来同步。

## 6. 判据（怎么算真做完了）

- 工具链：`lint` 0 错、`memory_check` 只剩软提醒。
- 打包：泄露扫描 0 命中、`zipfile.testzip()` 为 `None`。
- 注入：`hookcheck.py` 退出码说得清（0 四件齐 / 2 通道通但没交付 / 1 不通），**通道通 ≠ 记忆进了上下文**（`98` §6）。
- 文档：`CATALOG` 与路由表都跟得上实际文件；大纲与实际结构不打架。

## 7. 反模式（见过一次就记下来）

- 在 `fragments/` 里手改片段 → 下次 build 覆盖掉。
- 改完模块不 build 就说「存好了」 → 检索层还是旧的。
- 拆模块只改文件不改路由表 → 体检立刻报「文件未登记」。
- 编号改了一处不改引用 → 全库悬空引用（2026-10-20 重编号时踩过，扫了三轮才清干净）。
- 只看 `hook/result` 的 exitCode 就宣布「记忆注入了」 → `98` §5 逐条驳过。

## 8. 系统提示词这一层（未实现，原理先记）

记忆提示目前只进对话流（`UserPromptSubmit`），不进系统提示词；要常驻得用 DSH 的 `ctx.systemPrompt.section()` 注册固定段——签名、去重（同作用域重名抛错、agent 段遮蔽全局段）、排序（`-100` 身份 / `0` persona / `100–199` 工具）、`complete` 的危险、以及「段一变 KV cache 从首个变化 token 起失效」的代价，全记在 `93` §「system prompt 常驻段」。**为什么先不动手**：改 `dsh-genui` 之类第三方包往里塞记忆是反模式——升级即丢、星形开关一关连坐；正确做法是自己写一个独立插件注册这一层，等用户说了再动。
